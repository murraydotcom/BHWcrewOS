# CrewHQ patient messaging — BHW0000 candidate

`/bhw-portal-messages.html` is the operational inbox for authenticated Care Connect threads. It is linked from the CrewHQ tools list and uses the existing sign-in/return-route flow. It supports staff-initiated conversations, patient-visible replies, inbox status filters, authorized assignment, provider escalation, provider review, legal-record reference attestation and closure. It is independent of the public unmatched `portal-message.js` intake bridge and staff chat.

The server bridge uses the verified CrewOS session, signs a 60-second `portal-messaging` purpose token, and calls Health Core. Health Core's explicit active grants keyed by signed staff subject determine authority. Browser roles/job titles cannot grant access. The bridge hard-denies real-patient selection; Health Core also denies all identities outside BHW0000. Provider review/record-entry controls are enforced in the backend, not merely hidden in the interface.

Only the reply composer is shared with the patient. Escalation/review reasons, assignments, provider packets, audit metadata and record references remain in the staff workflow projection. Do not assume that interface privacy excludes responsive information from a records-access request. Messages are rendered as literal text, with no persistent browser message store. Unsaved drafts/retry state clear at session failure/expiry/page exit and 15 minutes of inactivity. Unconfirmed writes keep the original command/payload for retry.

Defaults remain off. A separately approved private synthetic target needs `SYNTHETIC_PORTAL_MESSAGING_ENABLED=true`, existing server-side `SESSION_SECRET` and `CREWHQ_CLOUD_TOKEN_SECRET`, HTTPS `HEALTH_CORE_API_URL`, and matching Health Core synthetic settings/grants. No token or secret is returned to the browser. This PR does not deploy, merge, activate real patient messages, or change external notifications.

Read means opened, not clinically reviewed. Staff must call the patient and follow existing urgent/escalation procedures when immediate action is needed. No monitored-hours or response-time promise is invented. The current candidate requires provider disposition before closure. Clinical correspondence requires entry in the authorized legal medical record followed by provider attestation to the exact conversation hash and chart reference. This is a manual attestation; it does not send/sign a chart note or prove an external EHR accepted an entry. CharmHealth is the configured default legal record during BHW's transition. An unauthorized authority choice is rejected. New correspondence requires fresh review.

See Health Core's `docs/portal-messaging-synthetic-review.md` for the full clinical/privacy/retention policy draft, protocol, acceptance evidence and remaining gates. Dependent backend and Care Connect PRs must be reviewed together.

Validation: selected staff regression suite 12/12 passing, including four new proxy tests. The integrated HTTP journey passes both directions, staff initiation, assignment/escalation/provider review/closure, hidden private notes, and denied anonymous/cross-role/ungranted access against an atomic transaction double. Browser, live Firestore/IAM/backup, full CI/build and clinical/privacy/security review remain pending. Real messaging has no enabled code path in this candidate.
