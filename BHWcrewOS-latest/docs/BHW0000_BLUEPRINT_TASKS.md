# BHW0000 persistent Blueprint tasks

Synthetic implementation under review; default off. Depends on Health Core #149 authority/actions, Health Core #136 and CrewOS #209/#212 results, and their messaging bases. Existing signed-note intake #217 is a different source contract and does not satisfy these task requirements.

Health Core owns the signed/released plan, candidate action decisions, clinical wording and completion condition. CrewOS receives reference/intent hashes, named owner, explicit timing/timezone/priority/prerequisites and reviewed-result reference metadata. It persists one deterministic task per source/action in the existing `tasks` collection name, with an index under `patientRequests/hc-blueprint-BHW0000`, transactional versions/audit and retry receipts. These live in an explicitly isolated synthetic database; no parallel clinical plan is copied.

Enable only with `SYNTHETIC_ONLY=true`, `SYNTHETIC_BLUEPRINT_TASKS_ENABLED=true`, isolated `BLUEPRINT_TASK_FIRESTORE_DATABASE`, exact HTTPS `HEALTH_CORE_BLUEPRINT_AUTHORITY_URL`, dedicated `BLUEPRINT_AUTHORITY_CREWOS_SECRET`, existing `CREWOS_OPERATIONS_TOKEN_SECRET` and explicit active named `BLUEPRINT_TASK_STAFF_GRANTS`. For example grants have `{active:true,role:"care-manager",name:"Synthetic reviewer"}` keyed by the exact staff subject, not a shared role. The patient projection requires a separate `BLUEPRINT_TASK_PROJECTION_SECRET` and binds the current source reference. No secrets are bundled into the browser.

The same-origin verified-staff bridge additionally needs `OPERATIONS_CLOUD_API_URL` and the default-off task flag. `bhw-blueprint-tasks.html` shows permitted owner work, due soon/today/overdue/completed views, reminder acknowledgment, returned-result references and completion after provider review. Provider/operations-manager all views support reconciliation. Missing owner/timing stay unresolved in Health Core; modified/revoked/superseded actions withdraw or block stale work, with history retained. Changed prerequisites require current-intent completion.

**Reminders are in-app and evaluated on explicit sync or each 30-second visible inbox refresh. There is no deployed background scheduler or external notification transport.** Acknowledgment, signing and mere result receipt do not complete clinical work. Completion requires Health Core's explicit provider review of the exact returned result and accepted action condition, followed by an explicit task transition.

The [Health Core contract](https://github.com/murraydotcom/bhw-health-core/blob/codex/blueprint-authority-20261021/docs/BHW0000_BLUEPRINT_AUTHORITY_AND_TASKS.md) has the complete source/permission/release/rollback contract. Keep flags disabled until protected synthetic candidate, runtime IAM, isolated storage and actual browser acceptance are verified. Retain task/audit history when rolling back. Do not enable real patients, lab exchange, orders, prescribing, claims or patient notifications.
